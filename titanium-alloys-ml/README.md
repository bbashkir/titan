# Система подбора и прогнозирования титановых сплавов

Локальное консольное приложение из двух модулей:

* **Модуль 1** — парсер открытых источников и база данных титановых сплавов (SQLite);
* **Модуль 2** — инструмент подбора: поиск похожих реальных сплавов (kNN + Random Forest)
  и генерация новых составов вариационным автокодировщиком (VAE), с экспортом отчёта в PDF.

---

## 0. Запуск в Docker (рекомендуется для демонстрации)

Ничего, кроме Docker Desktop, ставить не нужно — ни Python, ни библиотек.

Сборка образа (один раз, 3–10 минут в зависимости от скорости сети):

```bash
docker compose build
```

Демонстрация — база наполняется, модели обучаются, отрабатывают два готовых
сценария подбора, отчёты сохраняются в PDF:

```bash
docker compose up
```

Интерактивный подбор с меню и вводом своих значений:

```bash
docker compose run --rm app
```

| Команда | Что делает |
|---|---|
| `docker compose up` | демонстрация без ввода с клавиатуры, завершается сама |
| `docker compose run --rm app` | интерактивное меню подбора (основной режим) |
| `docker compose run --rm app --selftest` | самопроверка системы, 22 проверки |
| `docker compose run --rm app --stats` | статистика базы |
| `docker compose run --rm app --list` | все записи базы |
| `docker compose run --rm app --parse` | принудительное обновление базы |
| `docker compose up -d scheduler` | фоновое автообновление раз в месяц |
| `docker compose --profile "*" down` | остановить и удалить все контейнеры |

### Почему интерактивный режим запускается через `run`, а не через `up`

`docker compose up` подключает к контейнеру только вывод, но **не ввод** —
это штатное поведение Compose. Интерактивное меню в таком режиме зависло бы
на первом же вопросе, ожидая ответа, который до него не дойдёт. Поэтому:

* `docker compose up` поднимает сервис `demo` — он проходит все этапы работы
  системы на заранее заданных запросах и завершается сам;
* сервис `app` вынесен в профиль `interactive` и запускается командой
  `docker compose run`, которая подключает терминал полностью.

### Что сохраняется на компьютере

Три каталога проекта подключены к контейнеру как тома, поэтому результаты
остаются на диске после остановки:

* `data/` — база `alloys.db` и веса обученной модели;
* `logs/` — `parser.log`;
* `reports/output/` — готовые PDF-отчёты.

### Часовой пояс

По умолчанию контейнер живёт по UTC, и время в логах и отчётах разойдётся
с часами на компьютере. Задайте свой пояс перед запуском:

```bash
export TZ=Asia/Yekaterinburg
```

В Windows PowerShell:

```bash
$env:TZ="Asia/Yekaterinburg"
```

Размер собранного образа — около 1.3 ГБ (основное занимает PyTorch).
PyTorch ставится из индекса CPU-сборок: обычный пакет тянет библиотеки CUDA
на несколько гигабайт, которые здесь не нужны.

## 4. Режимы запуска

| Команда | Что делает |
|---|---|
| `python main.py` | Консольный инструмент прогнозирования (основной режим) |
| `python main.py --parse` | Разовый парсинг источников и обновление базы |
| `python main.py --schedule` | Автообновление базы по расписанию (раз в месяц) |
| `python main.py --schedule --now` | То же, но первый парсинг выполняется сразу |
| `python main.py --stats` | Статистика базы: записей, сплавов, источников |
| `python main.py --list` | Все записи, сгруппированные по названию сплава |
| `python main.py --selftest` | Сквозная самопроверка системы (22 проверки) |
| `python main.py --demo` | Демонстрация без ввода с клавиатуры |

Планировщик работает, пока открыто окно консоли. Остановка — `Ctrl+C`.
Чтобы он запускался вместе с Windows, добавьте в «Планировщик заданий»
задачу с действием `venv\Scripts\python.exe main.py --schedule`.

## 5. Работа с меню подбора

Меню выбора свойств:

```
  1  Плотность                     г/см³
  2  Прочность на растяжение       МПа
  3  Модуль упругости              ГПа
  4  Твёрдость по Бринеллю         HB
  5  Температура плавления         °C
  6  Коррозионная стойкость        low / medium / high
  7  Усталостная прочность         МПа
  8  Область применения            текст
  0  Готово — запустить прогнозирование
  с  сбросить все критерии
  в  выход
```

Выбирается любое подмножество параметров — незаданные при подборе игнорируются.
Для числовых свойств запрашиваются минимум и максимум; **пустое поле означает,
что граница не задаётся** (например, только минимум прочности — «от 900 МПа»).

Пример сеанса: подобрать сплав для авиации прочностью от 900 МПа
и плотностью до 4.6 г/см³.

```
Выберите пункт: 2
  минимум (МПа): 900
  максимум (МПа):

Выберите пункт: 1
  минимум (г/см³):
  максимум (г/см³): 4.6

Выберите пункт: 8
  Введите текст: авиация

Выберите пункт: 0
```

### Что выводится

**БЛОК А — похожие существующие сплавы (топ-5).** Название и источник,
химический состав, все известные свойства (отсутствующие — прочерком),
процент соответствия и объяснение, какие требования выполнены, какие нет.

**БЛОК Б — новые сгенерированные сплавы (топ-3).** Состав с конкретными
числами, предсказанные свойства, процент соответствия, обоснование состава
(роль каждого легирующего элемента, баланс альфа- и бета-стабилизаторов),
сравнение с ближайшим аналогом из базы и пометка о том, что сплав является
прогнозом модели.

**Краткое резюме** — какой вариант оптимален и почему.

После вывода программа предлагает сохранить отчёт в PDF. Ответ `д` — файл
появится в `reports/output/` с именем вида `titanium_report_20260814_153012.pdf`.

## 7. База данных

Файл `data/alloys.db`, таблица `alloys`. Одна запись — один сплав из одного
источника.

| Поле | Единицы | Описание |
|---|---|---|
| `id` | — | первичный ключ |
| `name` | — | название сплава (ВТ6, Ti-6Al-4V) |
| `source` | — | URL источника или обозначение стандарта |
| `chemical_composition` | % | JSON: `{"Ti": 89.4, "Al": 6.0, "V": 4.2}` |
| `density` | г/см³ | плотность |
| `melting_point` | °C | температура плавления |
| `tensile_strength` | МПа | предел прочности при растяжении |
| `yield_strength` | МПа | предел текучести |
| `elastic_modulus` | ГПа | модуль упругости |
| `hardness_brinell` | HB | твёрдость по Бринеллю |
| `corrosion_resistance` | — | `low` / `medium` / `high` |
| `thermal_conductivity` | Вт/(м·К) | теплопроводность |
| `fatigue_strength` | МПа | усталостная прочность |
| `application` | — | область применения |
| `parsed_at` | — | дата и время получения записи |

**Правила ведения базы**

* Параметр, не найденный в источнике, записывается как `NULL` и выводится прочерком.
* Один сплав из разных источников хранится отдельными записями: `name` совпадает,
  `source` различается. При выводе (`--list`) записи группируются по `name`.
* Дедупликация: совпадение `name` + `source` + химический состав — запись
  не добавляется повторно (уникальный индекс по этим полям).
* Если пара `name` + `source` уже есть, а состав отличается, запись добавляется
  как новый вариант данных и отмечается в логе отдельным счётчиком.
* Автообновление **только добавляет** записи; существующие никогда не изменяются
  и не удаляются.

Открыть базу вручную можно любым просмотрщиком SQLite (DB Browser for SQLite).

## 8. Источники данных

Работают по умолчанию:

| Источник | Тип | Комментарий |
|---|---|---|
| ГОСТ 19807-91, ОСТ 1 90013-81, ГОСТ 26492-85 | справочный | марочный состав и свойства отечественных сплавов |
| ASM Handbook Vol. 2, ASTM B265 | справочный | международные марки и Grade 1–23 |

Справочный набор даёт **47 записей по 43 сплавам из 7 источников** и работает
без интернета. Это гарантирует, что система полностью функциональна сразу после
установки.

Требуют настройки:

| Источник | Состояние | Что нужно |
|---|---|---|
| Semantic Scholar | включён, но пропускается | сервис отвечает `403` на запросы без ключа. Получите бесплатный ключ на <https://www.semanticscholar.org/product/api> и задайте его в переменной окружения `SEMANTIC_SCHOLAR_API_KEY` (в Windows: `setx SEMANTIC_SCHOLAR_API_KEY ваш_ключ`, затем перезапустите консоль) либо в `config.py` |
| ASM Aerospace Specification Metals | выключен | сайт `asm.matweb.com` отдаёт сертификат Cloudflare Origin CA, не подписанный публичным удостоверяющим центром: проверку TLS не проходит ни один клиент, а обращение по HTTP переадресуется на HTTPS. Парсер источника готов — включите `enabled: True` в `config.py`, когда сертификат исправят |

Выключены сознательно, с указанием причины:

| Источник | Причина |
|---|---|
| MatWeb, Total Materia | условия использования прямо запрещают автоматический сбор данных, доступ к полным карточкам платный |
| docs.cntd.ru, protect.gost.ru | контент отдаётся только авторизованным пользователям, роботы закрыты |
| elibrary.ru | требуется авторизация, автоматический сбор запрещён |
| ResearchGate | активная защита от автоматических обращений |

Проверка сертификатов **не отключается ни для одного источника**: приём
непроверенного соединения означал бы возможность подмены данных, попадающих
в базу. Источник с недействительным сертификатом пропускается, причина
записывается в лог.

Данные этих источников (тексты ГОСТов, справочные значения) внесены в
`parser/reference_data.py` вручную с указанием конкретного стандарта в поле
`source` — так база остаётся достоверной и прослеживаемой.

Парсер перед каждым обращением проверяет `robots.txt`, выдерживает паузу
между запросами (`config.REQUEST_DELAY`, по умолчанию 3 секунды) и повторяет
запрос при сетевой ошибке. Чтобы подключить дополнительный источник,
переключите его `enabled` в `config.py` и реализуйте класс-наследник
`BaseSource` в `parser/scraper.py`.

## 9. Как устроены модели

### Поиск похожих сплавов (`ml/similarity_model.py`)

1. **Random Forest** обучается предсказывать каждое свойство по химическому
   составу и заполняет пропуски в базе. Восстановленные значения используются
   **только для геометрии поиска** — в отчёте на их месте по-прежнему прочерк.
2. **kNN** (`NearestNeighbors`) отбирает кандидатов в подпространстве тех
   свойств, которые задал пользователь.
3. Кандидаты ранжируются по проценту соответствия, посчитанному на реальных
   значениях; для каждого формируется текстовое объяснение.

Процент соответствия: каждый заданный критерий даёт оценку от 0 до 1
(попадание в диапазон — 1, отклонение снижает оценку пропорционально ширине
запроса, коэффициент `config.TOLERANCE_RATIO`), итог — среднее по критериям.
Критерий, по которому в источнике нет данных, засчитывается как 0.5 и выносится
в отдельный список «нет данных».

### Генерация новых сплавов (`ml/generative_model.py`)

Вариационный автокодировщик на PyTorch: энкодер сжимает вектор состава
(16 элементов) в латентное пространство размерности 4, декодер восстанавливает
состав через `softmax`.

Гарантии корректности:

* `softmax` на выходе — сумма долей всегда ровно 100 %;
* составы с содержанием титана ниже `config.GEN_MIN_TI` (50 %) отбраковываются;
* элементы с долей меньше `config.GEN_MIN_ELEMENT` отбрасываются, остаток
  перенормируется — как в реальной марочной записи;
* кандидат отбрасывается, если он ближе `config.GEN_NOVELTY_THRESHOLD`
  (норма L1 в процентных пунктах) к любому сплаву из базы — модель обязана
  предлагать именно новые комбинации.

Свойства сгенерированных составов предсказываются теми же регрессорами
Random Forest, коррозионная стойкость — классификатором Random Forest,
область применения оценивается по ближайшему аналогу из базы.

Веса VAE сохраняются в `data/vae_model.pt` и переобучаются при каждом
запуске (обучение занимает секунды, база небольшая).

## 12. Типичные проблемы

**`ModuleNotFoundError: No module named 'rich'`** — не активировано виртуальное
окружение. Выполните `venv\Scripts\activate` и повторите запуск.

**В PDF вместо русских букв чёрные квадраты** — не найден TTF-шрифт.
Проверьте, что существует `C:\Windows\Fonts\arial.ttf`, либо добавьте путь
к своему шрифту в начало списка `PDF_FONT_CANDIDATES` в `config.py`.

**«База данных пуста»** — выполните `python main.py --parse`.

**Парсинг сетевых источников ничего не добавил** — это ожидаемо: без ключа API
Semantic Scholar пропускается, ASM отключён из-за недействительного сертификата
(см. раздел 8). Причина каждого пропуска записывается в `logs/parser.log`,
справочные данные загружаются в любом случае, и система полностью работоспособна.

**Долгая установка `torch`** — поставьте CPU-сборку отдельно:
`pip install torch --index-url https://download.pytorch.org/whl/cpu`

## 13. Ограничения

* Значения в блоке Б — **прогноз статистической модели**, обученной на
  небольшой выборке. Это инструмент для сужения области поиска, а не замена
  металловедческого расчёта и испытаний.
* Точность предсказания свойств растёт с объёмом базы: чем больше источников
  подключено и чем больше накоплено записей, тем осмысленнее генерация.
